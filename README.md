# Foundations Practice

An independent, offline practice app for Claude solution architect foundations. It includes a timed exam, guided study mode, topic drills, answer explanations, and a locally saved latest score. Questions are original study material and are not official exam content; the app is not affiliated with Anthropic.

## Prerequisites

Use Node.js 22.13+ or 24.3+ (Node 24 LTS is recommended) and Java 17 or newer. Android emulation also needs Android SDK platform-tools, the emulator, an Android platform/build-tools version, a system image, and hardware virtualization.

On this Windows machine, Node 24.21.0, Temurin JDK 21, Android API 36/build-tools 36.1.0, platform-tools, the emulator, and a Google Play x86_64 system image are installed under the user profile. The Pixel 7 AVD is named `Foundations_API_36`, and WHPX acceleration is available.

After installing or changing these tools, restart VS Code so new terminals inherit the configured paths. This workspace uses Command Prompt.

The integrated terminal gets its paths from [.vscode/settings.json](.vscode/settings.json), which prepends `JAVA_HOME\bin`, the Android SDK tools, and `%NODE_HOME%` to `PATH`. `NODE_HOME` must be a user environment variable that points to the folder containing `node.exe` (here, `%LOCALAPPDATA%\Programs\node-v24.21.0\node-v24.21.0-win-x64`). An older global Node 18 and Java 11 are also on the system `PATH`. If `NODE_HOME` is missing, or you work in a terminal outside VS Code, those older versions win, and `expo-doctor` and the build fail. Before running anything, check:

```sh
node -v      # v24.x
java -version  # 21.x
adb version
```

## Run locally

```sh
npm ci
emulator -avd Foundations_API_36
npx expo run:android
```

Run `emulator` in its own terminal, because it keeps running in the foreground. Run the build in a second terminal after the emulator has booted.

This app uses a native AdMob module and cannot run in Expo Go. `npx expo run:android` builds and installs the development client on the emulator. Once it's installed, use `npm start` to start Metro and reload JavaScript changes without a native rebuild. Rebuild with `npx expo run:android` after changing `app.json` plugins, native dependencies, or app IDs. The `android/` folder is generated by prebuild and is git-ignored, so don't edit it by hand.

`npm run ios` needs macOS with Xcode. Only the Android flow is set up on this machine.

### Run without ads

```sh
set EXPO_PUBLIC_DISABLE_ADS=true
npx expo prebuild --clean --platform android
npx expo run:android
```

The `set` command applies only to the current Command Prompt window, so run the build in that same window. The JavaScript side of the flag is read when Metro bundles, so restart Metro with `npx expo start --clear` after changing it. The native side, which removes the advertising ID permission, only changes after `npx expo prebuild --clean`. To go back to ads, close the window (or run `set EXPO_PUBLIC_DISABLE_ADS=`) and repeat the prebuild and run steps. See [Disabling ads](#disabling-ads) for what the flag changes.

### Test a release build locally

Before publishing, run a release build on the emulator. It bundles the JavaScript into the app, needs no Metro server, and behaves like the store build:

```sh
npx expo run:android --variant release
```

Local release builds are signed with the debug key, so they can't be uploaded to Play Console; use EAS for the store bundle (see [Build for Google Play](#build-for-google-play)). Release builds don't use Google's test ad unit. Without `EXPO_PUBLIC_ADMOB_INTERSTITIAL_ID` they show no ads. If you set a real interstitial ID, don't tap the ads, because clicking your own live ads can get your AdMob account suspended. To check the ad-free version, set `EXPO_PUBLIC_DISABLE_ADS=true` and run the prebuild step from [Run without ads](#run-without-ads) first.

## Project layout

- [App.tsx](App.tsx): the whole app, including the question bank (`QUESTIONS`), session logic, ad handling, and styles.
- [app.json](app.json): Expo config, app IDs, and the AdMob config plugin.
- [eas.json](eas.json): EAS build profiles (`development`, `preview`, `production`).

## Question bank

Questions live in the `QUESTIONS` array in [App.tsx](App.tsx). Each one needs a unique `id`, one of the four `Topic` values, four options with distinct text (option text is used as the React key), the zero-based `answer` index, an `explanation`, and a `source`. The `source` has a `title`, an optional `section`, a `url` (with a `#heading` anchor when the page has one), and a `quote` copied word for word from that page. Study mode and the results review show the quote and link to the source. Check that the quote actually appears on the linked page before adding a question. Topic counts on the home screen come from the array, so no other changes are needed.

Each session shuffles the question order and the option order, so where the correct option sits in the source doesn't matter. Option *length* does matter: keep distractors about as long and as plausible as the correct answer, or the longest option gives the answer away. The bank has 60 questions, 15 per topic. The timed exam can be either 10 random questions or all 60, chosen on the home card, with 2 minutes per question (20 or 120 minutes). Study mode uses the whole bank, and the quick set uses 5 questions.

## Ads

Development builds use Google's sample AdMob app IDs and Google's test interstitial unit ID. Interstitials are requested after every 10 distinct answers; the timed exam pauses while an ad loads or displays, then resumes after it closes. If an ad fails to load within 8 seconds, the session continues without it. In development builds, every ad step is logged to the Metro terminal as `[ads] …`.

[app.config.js](app.config.js) reads the AdMob App IDs from `ADMOB_ANDROID_APP_ID` and `ADMOB_IOS_APP_ID`, and falls back to Google's sample IDs when they are unset. The interstitial unit ID comes from `EXPO_PUBLIC_ADMOB_INTERSTITIAL_ID`. EAS **production** builds fail if the App ID for the target platform or the interstitial ID is missing, so test IDs can't reach the Play Store. The `preview` profile is also a release build, but it doesn't use the test interstitial ID, so it shows no ads unless you set `EXPO_PUBLIC_ADMOB_INTERSTITIAL_ID` for it.

Set the values in the EAS `production` environment. A local `.env` file is not uploaded to EAS cloud builds, and `EXPO_PUBLIC_*` values are inlined into the JavaScript bundle at build time. Ad IDs are not secret.

```sh
eas env:create --name ADMOB_ANDROID_APP_ID --value ca-app-pub-xxx~yyy --environment production --visibility plaintext
eas env:create --name EXPO_PUBLIC_ADMOB_INTERSTITIAL_ID --value ca-app-pub-xxx/zzz --environment production --visibility plaintext
```

### Disabling ads

Set `EXPO_PUBLIC_DISABLE_ADS=true` to build the app without ads. The app then never runs the consent flow, never initializes the ads SDK, and never pauses for an ad break, and the Privacy choices button doesn't appear. [app.config.js](app.config.js) skips the AdMob ID checks and removes the `com.google.android.gms.permission.AD_ID` permission from the manifest. The ads SDK is still linked into the binary because `App.tsx` imports it, but it makes no ad requests.

The `preview-noads` and `production-noads` EAS profiles set the flag for you (`npm run build:android:noads` builds the store bundle). To run without ads locally, see [Run without ads](#run-without-ads).

### Consent

Before initializing ads, the app runs Google's User Messaging Platform consent flow (`AdsConsent.gatherConsent()`). Users in regions that require consent, such as the EEA, the UK and Switzerland, see Google's consent form. Ads are requested only when the result allows it. When consent applies to the user, a **Privacy choices** button on the home screen reopens the form. Before going live, create and publish a GDPR consent message for the app under **Privacy & messaging** in AdMob; without one, users in those regions get no consent form and no ads.

`npx expo install --check` prints a warning that the root-level `"react-native-google-mobile-ads"` key in `app.json` is ignored by the Expo config. That is expected. The library's native build reads the key directly, while Expo reads only the plugin entry.
## Test

Run the available static checks:

```sh
npx tsc --noEmit
npx expo-doctor
```

Then exercise these flows in the emulator:

- Timed exam: answer, flag and revisit a question, finish the exam, and review the score and answer explanations. Repeat with the "All 60" length and confirm the clock starts at 120:00.
- Study mode: check both a correct and incorrect answer, read the explanation, and finish the session.
- Quick set and topic drills: confirm the quick set has five questions and topic drills contain only their selected topic.
- Persistence: finish a session, return to the practice desk, and confirm the latest result remains after restarting the app.
- Ads: use the test ad unit, verify an interstitial after answers 10, 20, and 30 in study mode, and verify the timed clock remains unchanged while loading/showing and resumes after dismissal.

There is no automated UI test suite configured yet; the flows above are manual emulator checks.

## Build for Google Play

1. The Android application ID is `com.sweb.foundationspractice`. It becomes permanent with the first store upload. After changing it, run `npx expo prebuild --clean --platform android` before the next local build.
2. Install the EAS CLI (`npm install -g eas-cli`), then sign in to an Expo account with `eas login` and link this project with `eas build:configure`.
3. Build an installable preview APK with `eas build --platform android --profile preview`, or `--profile preview-noads` for the ad-free version. Install it on a phone from the link EAS prints, and test it there before building for the store.
4. Build the Play Store Android App Bundle with `npm run build:android` (the `production` profile, with ads), or `npm run build:android:noads` (the `production-noads` profile, without ads). Download the `.aab` from the link EAS prints and upload it under a release in Play Console, or submit it with `eas submit --platform android`.
5. Complete the Play Console listing, content rating, privacy policy, and Data safety declaration before submission. The app keeps only the latest practice result on-device and has no account or app backend.
   - With ads: the Google Mobile Ads SDK collects data, including the advertising ID, device information, and diagnostics. Declare that in Data safety, answer **Yes** to "Does your app use advertising ID?", and declare that the app contains ads.
   - Without ads: declare that the app does not contain ads, and answer **No** to the advertising ID question; the `AD_ID` permission is removed from the manifest.

The `production` EAS profile increments Android version codes. A Play Console developer account and signing/build credentials are required to publish; they are not included in this repository.
